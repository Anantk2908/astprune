\title{Learned AST Pruning for Token-Budgeted Code Context}

\author{\IEEEauthorblockN{Anant Kumar}

\maketitle

\begin{abstract}
Coding agents read whole source files, although most of a file is irrelevant to the bug at hand. We train a small ranker that decides, function by function, what an agent should see under a fixed token budget. Files are split into functions, methods and classes with tree-sitter. A 125M-parameter encoder, fine-tuned with a contrastive loss on \stat{examples:examples} real bug fixes, scores each unit against the issue text, and a selector keeps the best units whole, shows the next ones as signatures and drops the rest, so the result is always valid Python. On SWE-bench Lite, with the gold files and their imports as candidates, the pruner keeps \res{lite:oracle_imports:ast_trained:r0.10:gold_fn_recall}\% of the functions changed by the gold patch at a 10\% budget and \res{lite:oracle_imports:ast_trained:r0.25:gold_fn_recall}\% at 25\%, against \res{lite:oracle_imports:ast_bm25:r0.10:gold_fn_recall}\% and \res{lite:oracle_imports:ast_bm25:r0.25:gold_fn_recall}\% for BM25 over the same units and \res{lite:oracle_imports:chunk_bm25:r0.10:gold_fn_recall}\% and \res{lite:oracle_imports:chunk_bm25:r0.25:gold_fn_recall}\% for BM25 over text chunks. The gain from training is largest at tight budgets and shrinks as the budget grows. The pruner is served as a Model Context Protocol tool. All tuning used a separate validation split, and every number is regenerated from released per-issue results.
\end{abstract}
